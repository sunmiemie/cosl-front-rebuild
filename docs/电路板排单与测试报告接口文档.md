# 电路板排单与测试报告接口文档

更新时间：2026-07-01

## 1. 接口说明

本文档说明电路板测试工单在数字化测试管理系统中的排单接口，以及与工程师小助手对接的测试报告接口。

电路板模块的排期方式与高温高压井、振动台、水循环等工单不同：

- 电路板排期不填写开始时间、结束时间。
- 电路板排期只保存排期顺序。
- 页面左侧为待排程工单，右侧为已排程顺序列表。
- 拖入右侧后按顺序测试，例如第 1 个、第 2 个、第 3 个。

## 3. 电路板排单接口

### 3.1 保存电路板排期顺序

用于电路板模块拖拽排单。

```http
POST /test/circuit-board-module/order/schedule/{order_id}/
```

### 请求参数

路径参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `order_id` | 是 | 本系统电路板申请单/工单 ID |

请求体：

```json
{
  "sequence_only": true,
  "sequence_order": 1
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sequence_only` | boolean | 是 | 固定传 `true`，表示仅保存排期顺序 |
| `sequence_order` | number | 是 | 排期顺序，从 `1` 开始 |

### 成功响应

```json
{
  "code": 0,
  "msg": "排期顺序已保存",
  "data": {
    "scheduledStartAt": null,
    "scheduledEndAt": null,
    "scheduleSegments": [
      {
        "sequence_only": true,
        "sequence_order": 1
      }
    ]
  }
}
```

### 失败响应示例

当前状态不可排期：

```json
{
  "code": -1,
  "msg": "当前状态不可排期：0"
}
```

排期顺序为空或非法：

```json
{
  "code": -1,
  "msg": "排期顺序不能为空"
}
```

### 业务规则

- 只允许状态为 `1` 或 `2` 的电路板工单排期。
- `1` 表示待领取/待排程。
- `2` 表示测试中。
- 电路板排期不保存时间段，因此 `scheduledStartAt` 和 `scheduledEndAt` 固定为 `null`。
- 排期顺序保存在 `scheduleSegments[0].sequence_order` 中。

## 4. 取消电路板排期

用于从右侧已排程顺序列表中移除电路板工单。

```http
DELETE /test/circuit-board-module/order/schedule/{order_id}/
```

### 请求参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `order_id` | 是 | 本系统电路板申请单/工单 ID |

### 成功响应

```json
{
  "code": 0,
  "msg": "排期已取消",
  "data": {
    "scheduledStartAt": null,
    "scheduledEndAt": null,
    "scheduleSegments": []
  }
}
```

## 5. 电路板排单数据示例

例如电路板模块右侧顺序为：

| 顺序 | 申请单号 | 项目名称 |
| --- | --- | --- |
| 1 | `CS20260701003` | 工程师小助手科研项目 |

}

保存第二个工单：

```http
POST /test/circuit-board-module/order/schedule/1/
```

```json
{
  "sequence_only": true,
  "sequence_order": 2
}
```

## 6. 与小助手排期同步说明

当前电路板模块没有时间段排期，因此不应向小助手传 `startTime`、`endTime` 表示几点到几点。

如果需要通知小助手“已排单”，建议只同步状态或顺序类信息，例如：

```json
{
  "id": "20",
  "testType": "6",
  "status": "6",
  "description": "电路板测试工单已排单，排期顺序：1"
}
```

对应本系统代理接口：

```http
POST /external/assistant/change-status/
```

请求体示例：

```json
{
  "id": "20",
  "testType": "6",
  "status": "6",
  "description": "电路板测试工单已排单，排期顺序：1"
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 小助手申请单 ID，例如 `CS20260701003` 对应的小助手 `testId=20` |
| `testType` | 是 | 电路板测试类型，固定为 `6` |
| `status` | 是 | 小助手状态值，`6` 表示已排单 |
| `description` | 是 | 状态说明 |

成功响应：

```json
{
  "code": 0,
  "msg": "外部工程师助手同步成功",
  "data": {}
}
```

## 7. 测试报告推送接口

用于把数字化测试管理系统生成的电路板测试报告回传给工程师小助手。

```http
POST /external/assistant/push-reports/
```

### 请求体

```json
{
  "testReportList": [
    {
      "id": "20",
      "testType": "6",
      "status": "9",
      "data": [
        {
          "filename": "CS20260701003-report.pdf",
          "equipmentId": "MD150-018",
          "fileContent": "JVBERi0xLjQK...",
          "description": "电路板测试报告",
          "status": "已完成"
        }
      ]
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `testReportList` | array | 是 | 报告列表 |
| `testReportList[].id` | string | 是 | 小助手申请单 ID |
| `testReportList[].testType` | string | 是 | 电路板测试类型，固定为 `6` |
| `testReportList[].status` | string | 是 | 小助手申请单状态，完成通常传 `9` |
| `testReportList[].data` | array | 是 | 报告文件列表 |
| `data[].filename` | string | 是 | 报告文件名 |
| `data[].equipmentId` | string | 是 | 样品 SN 或样品内部标识 |
| `data[].fileContent` | string | 是 | 报告文件 Base64 内容 |
| `data[].description` | string | 是 | 报告说明 |
| `data[].status` | string | 是 | 报告状态文案 |

### 注意事项

- `fileContent` 必须传 Base64 文件内容，不传文件 URL。
- 如果样品有真实 SN，`equipmentId` 建议传真实 SN，例如 `MD150-018`。
- 如果样品无真实 SN，例如线束样品小助手传来的 SN 为 `-`，可传本系统内部样品标识或申请单号加样品 ID，例如 `CS20260701003-047`。
- `testType=6` 表示电路板测试。
- `status=9` 表示已完成。

### 成功响应

```json
{
  "code": 0,
  "msg": "外部工程师助手同步成功",
  "data": {}
}
```

## 8. 本地报告查询接口

### 8.1 查询正式测试报告列表

```http
GET /data/assistant/report/list?reportType=report&limit=2000
```

响应示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "list": [
      {
        "id": 1,
        "name": "报告名称",
        "status": 0,
        "date": "2026-07-01 10:00:00",
        "testunitId": 245,
        "fileName": "report.json",
        "pdfFileName": "report.pdf",
        "downloaded": false,
        "downloadUrl": "/data/report/download?name=report.json",
        "pdfDownloadUrl": "/data/report/pdf/download?id=1"
      }
    ],
    "total": 1,
    "reportType": "report"
  }
}
```

### 8.2 查询临时测试报告列表

```http
GET /data/assistant/report/list?reportType=dev_report&limit=2000
```

响应字段与正式测试报告一致，其中 `testunitId` 对应临时测试工单 ID。

## 10. 电路板测试字段约定

| 字段 | 说明 |
| --- | --- |
| `testType` | 电路板测试固定为 `6` |
| `id` | 小助手申请单 ID，即接口返回中的 `testId` |
| `orderNo` | 本系统电路板申请单号，例如 `CS20260701003` |
| `sequence_order` | 电路板排单顺序 |
| `sequence_only` | 是否为纯顺序排单，电路板固定为 `true` |
| `scheduledStartAt` | 电路板不使用，固定为 `null` |
| `scheduledEndAt` | 电路板不使用，固定为 `null` |

## 11. 状态建议

| 状态值 | 含义 |
| --- | --- |
| `6` | 已排单 |
| `9` | 已完成 |

电路板排单完成后，如需同步小助手，建议调用 `/external/assistant/change-status/`，传 `status=6`。

电路板报告生成并确认后，建议调用 `/external/assistant/push-reports/`，传 `status=9` 并携带报告 Base64。
