# 多时间段工单排程设计

## 背景

工单排程需要支持一个工单拆分到多个不连续时间段。例如同一个工单可以安排为：

- 2026-06-15 11:00 到 2026-06-15 13:00
- 2026-06-16 09:00 到 2026-06-16 12:00

该能力需要覆盖工单排程中的全部类型：高温高压井、HALT-HASS、振动台、水循环、模拟井、高温箱、电路板模块。

## 当前状态

前端排程页已经存在 `scheduleSegments` 字段，并且日历渲染逻辑会优先读取多个时间段，再回退到单个 `scheduledStartAt` / `scheduledEndAt`。后端多个模型也已经存在 `schedule_segments` JSON 字段，但当前管理端弹窗仍然只允许录入一个日期、开始时间和时长。

因此这次改造不需要重建排程体系，核心是把单段录入升级为多段录入，并保证所有工单类型保存、读取、清空排程时都使用同一套字段语义。

## 数据结构

以 `schedule_segments` 作为主数据，每个元素代表一个独立排程时间段：

```json
{
  "scheduled_start_at": "2026-06-15 11:00:00",
  "scheduled_end_at": "2026-06-16 12:00:00",
  "schedule_segments": [
    {
      "scheduled_start_at": "2026-06-15 11:00:00",
      "scheduled_end_at": "2026-06-15 13:00:00"
    },
    {
      "scheduled_start_at": "2026-06-16 09:00:00",
      "scheduled_end_at": "2026-06-16 12:00:00"
    }
  ]
}
```

字段规则：

- `schedule_segments` 是真实排程明细，日历方块按它渲染。
- `scheduled_start_at` 保存所有时间段中最早的开始时间，用于兼容旧状态判断和列表排序。
- `scheduled_end_at` 保存所有时间段中最晚的结束时间，用于兼容旧状态判断和列表排序。
- 如果只排一个时间段，也必须保存为一个元素的 `schedule_segments`。
- 清空排程时，三个字段都清空：`scheduled_start_at = null`、`scheduled_end_at = null`、`schedule_segments = []`。

## 前端交互

排程弹窗从单段表单改成时间段列表：

- 顶部仍显示工单号和排程对象。
- 下方显示多行时间段，每行包含日期、开始时间、结束时间、删除按钮。
- 默认打开时：
  - 已有 `scheduleSegments` 时回填全部时间段。
  - 只有旧的 `scheduledStartAt` / `scheduledEndAt` 时回填为一个时间段。
  - 没有排程时默认生成一行，日期使用当前选中周/日期，时间可默认为 09:00 到 11:00。
- 提供“添加时间段”按钮，追加一行新的时间段。
- 保存时把所有行转换为 `schedule_segments`，并计算最早开始和最晚结束。

日历显示：

- 一个工单的每个时间段都渲染为独立方块。
- 同一个工单跨多天时，会在对应日期列分别显示。
- 左侧工单卡片可以展示“已排程 2 段”或“共 5h”，用于提示该工单不是单段排程。

## 校验规则

前端保存前校验：

- 至少保留一个有效时间段。
- 每段必须有日期、开始时间和结束时间。
- 开始时间必须早于结束时间。
- 时间必须在排程日历工作时间范围内，即 06:00 到 22:00。
- 同一工单内部的时间段不能完全重复。

后端保存时做同等兜底校验，避免测试端或旧客户端传入异常数据。

可选增强：同一设备同一时间段是否允许被多个工单占用。如果业务要求严格占用，可以在后端增加冲突检测；如果允许人工并排安排，则先不阻断，只由界面展示重叠。

## 后端接口

所有工单类型的排程保存接口统一接收：

```json
{
  "scheduled_start_at": "2026-06-15 11:00:00",
  "scheduled_end_at": "2026-06-16 12:00:00",
  "schedule_segments": [
    {
      "scheduled_start_at": "2026-06-15 11:00:00",
      "scheduled_end_at": "2026-06-15 13:00:00"
    }
  ]
}
```

需要统一检查以下设备接口：

- `water-cycle`
- `vibration-table`
- `high-temp-pressure`
- `halt-hass`
- `simulated-well`
- `high-temp-box`
- `circuit-board-module`

其中已经支持 `schedule_segments` 的接口保留现有逻辑；只保存单段字段的接口需要补齐 `schedule_segments` 字段保存和序列化。

## 测试计划

前端测试：

- 打开已有多段排程工单时，弹窗回填多行。
- 保存两个时间段时，请求 payload 带两个 `schedule_segments`。
- 日历按两个时间段渲染两个方块。
- 删除一个时间段后，只保存剩余时间段。
- 单段旧数据仍能回填并保存为一个 `schedule_segments`。

后端测试：

- 每个工单类型保存多个时间段后，数据库中 `schedule_segments` 保留全部段。
- `scheduled_start_at` 为最早开始时间，`scheduled_end_at` 为最晚结束时间。
- 删除排程后，三个排程字段全部清空。
- 非法时间段返回错误，不写入数据库。

## 实施边界

本次只实现工单排程多时间段能力，不调整工单状态流转，不新增独立排程明细表，不改变测试端日历的读取字段。测试端继续读取同一后端排程数据，因此管理端保存多段后，测试端日历应同步显示多个排程方块。
