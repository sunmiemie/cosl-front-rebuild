# 电路板模块管理端设计

## 背景

管理端需要在“测试管理 / 电路模块检验 / 电路板模块”中接入电路板模块界面。界面参考用户提供 HTML 中的“电路板模块”区域，但视觉风格必须服从当前系统的 Element Plus 中后台样式。现有系统中，设备管理的电路板详情表存在两套二维码行为：行内“二维码”打开预览弹窗，批量“打印二维码”调用 `getQRcodeImgApi` 后打开打印窗口。本次新页面只使用打印行为，不使用二维码弹窗。

## 目标

- 在 `src/views/testmanage/circuit-module-inspection/index.vue` 的“电路板模块”标签页中替换占位内容。
- 新增独立组件承载电路板模块界面，避免把设备管理页面的导入、编辑、弹窗等逻辑带入测试管理。
- 电路板模块列表支持查看模块详情，并在模块级直接打印该模块下全部电路板二维码。
- 电路板明细表支持单块电路板直接打印二维码。
- 页面不显示“开始测试”按钮。
- 点击“二维码”或“打印二维码”时不显示二维码弹窗。

## 非目标

- 不改造生产电路板、临时电路板原有页面的弹窗行为。
- 不新增后端接口契约，优先使用当前前端已有 API；如果现有接口不足，只在前端预留清晰封装点。
- 不复制参考 HTML 中的测试流程按钮、优先级队列、模拟数据和弹窗二维码逻辑。

## 页面结构

采用 A 方案：新增 `CircuitBoardModule.vue` 组件，并挂载到“电路板模块”标签页。

页面内部采用左右布局：

- 左侧为电路板模块列表，展示模块编号、模块名称、来源类型、状态、电路板数量、创建时间。
- 右侧为选中模块详情，顶部显示模块基础信息，底部显示该模块下电路板表格。
- 操作按钮只保留和管理端当前场景相关的动作：详情、打印二维码、刷新、查询、重置。

模块列表上的“打印二维码”打印该模块下所有电路板。右侧电路板表格行内“打印二维码”打印当前单块电路板。

## 数据流

电路板模块列表以“工单/申请单”为模块单位。每条模块记录需要包含或能够查询到该模块下的全部电路板列表。

实现时先封装数据适配层：

- 模块列表查询函数负责返回模块基本信息和电路板数量。
- 模块详情查询函数负责返回模块详情及其电路板列表。
- 电路板数据在进入打印逻辑前统一整理成二维码接口可识别的字段结构。

如果模块数据来自已有 HALT-HASS/电路板组相关接口，优先复用已有订单-电路板关联数据；如果当前后端返回字段和打印接口字段不一致，在组件内做轻量字段映射，不改变后端数据含义。

## 二维码打印逻辑

复用现有系统的二维码图片接口：

- `src/api/qrcode/index.ts`
- `getQRcodeImgApi`

新增一个前端打印辅助函数，统一处理：

1. 校验待打印电路板列表不为空。
2. 调用 `getQRcodeImgApi` 获取二维码图片。
3. 使用 `window.open("", "_blank")` 打开打印窗口。
4. 将接口返回的二维码图片写入打印窗口。
5. 调用 `printWindow.print()`。
6. 打印窗口打开失败时提示“无法打开打印窗口”。

新页面不引入 `qrcode.vue`，不声明 `qrcodeVisible`，不渲染二维码弹窗。

## 状态与交互

- 页面首次进入时加载模块列表，并默认选中第一条模块。
- 查询条件变化后刷新模块列表，列表为空时右侧显示空状态。
- 点击模块行或“详情”时刷新右侧明细。
- 模块级打印以当前模块下全部电路板为数据源，不依赖表格勾选。
- 单板打印以当前行作为数据源。
- 如果模块下没有电路板，打印按钮给出提示，不调用接口。

## 测试与验证

需要覆盖以下验证点：

- “电路板模块”标签页不再显示占位空状态。
- 页面源码中不出现“开始测试”按钮。
- 新组件不使用 `qrcode.vue` 弹窗逻辑。
- 模块级打印调用二维码接口时传入的是该模块下全部电路板。
- 单板打印调用二维码接口时只传入当前行。
- 打印窗口打开失败时有错误提示。
